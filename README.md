# مطعم العمدة — دليل المشروع الكامل (Supabase Edition)

هذا الملف يشرح كل حاجة اتعملت في المشروع، وفين تحط كل كود، وإزاي تشغّل المشروع
على جهازك في Visual Studio Code خطوة بخطوة، من الصفر لحد ما توصل لموقع شغال
متصل بقاعدة بيانات حقيقية.

---

## 1) اللي اتغيّر في المشروع (ملخص)

| القديم | الجديد |
|---|---|
| Cloudflare D1 + Worker (`worker/index.ts`, `wrangler.toml`, `schema.sql` بصيغة SQLite) | **Supabase** (PostgreSQL + Auth + Storage + Realtime) |
| سيرفر Express فيه كل الـ API (`server.ts` بـ 939 سطر) | سيرفر بسيط جداً بيقدّم الموقع بس (الفرونت إند بيكلم Supabase مباشرة) |
| تسجيل دخول الأدمن بتوكن مصنوع يدوياً | **Supabase Auth** حقيقي (Email + Password) |
| تعديل ينزل على العميل فوراً بدون مراجعة | نظام **مسودة (Draft) / منشور (Published)** حقيقي + زر **"🚀 رفع التعديلات"** |
| تبويبات الكاشير، أرشيف المبيعات، الجرد | **اتشالت بالكامل** (الموقع أصبح منيو وطلب عبر واتساب فقط، زي ما طلبت) |
| رفع الصور base64 داخل الكود | رفع حقيقي إلى **Supabase Storage** ورابط عام دائم |
| إنترو المقدمة (2.5 ثانية) | نفس المدة تقريباً، لكن بطبقات بصرية أعمق (دخان، موجة حرارة، خط ضوء يعبر الشاشة، دائرتين دوّارتين) بدون مبالغة أو تأثير على الأداء |
| بطاقات السوشيال ميديا | **مكوّن عام واحد** (`SocialMediaCards.tsx`) داخل الفوتر العام (`Footer.tsx`) الظاهر في كل صفحة — 3 بطاقات جنب بعض دايماً على الموبايل، ومتحكم فيها بالكامل من الأدمن |

## 2) هيكل المشروع (فين تلاقي كل حاجة)

```
├── schema.sql                      ← كود SQL الكامل لقاعدة بيانات Supabase (شغّله في Supabase)
├── .env.example                    ← انسخه باسم .env وحط فيه بيانات Supabase
├── src/
│   ├── lib/
│   │   └── supabaseClient.ts       ← الاتصال بـ Supabase + رفع الصور
│   ├── context/
│   │   └── StoreContext.tsx        ← كل منطق البيانات: قراءة المنشور، تعديل المسودة، النشر، تسجيل الدخول
│   ├── types.ts                    ← أشكال البيانات (منتج، قسم، إعدادات، سوشيال ميديا...)
│   ├── data/initialData.ts         ← بيانات افتراضية تظهر فقط لو الاتصال بـ Supabase فشل مؤقتاً
│   ├── components/
│   │   ├── cinematic/CinematicIntro.tsx    ← الإنترو السينمائي
│   │   ├── cinematic/AmbientBackground.tsx ← الخلفية الحية المستمرة (نفس عالم الإنترو يكمل في الموقع)
│   │   ├── common/SocialMediaCards.tsx     ← مكوّن الكروت الثلاثة (عام لكل الموقع)
│   │   ├── common/Footer.tsx               ← الفوتر العام اللي بيستدعي SocialMediaCards
│   │   ├── common/WhatsAppWidget.tsx       ← زر الواتساب العائم (يفتح السلة أو استفسار عام)
│   │   ├── common/CartModal.tsx            ← نافذة مراجعة السلة وإرسال الطلب لواتساب
│   │   └── admin/
│   │       ├── AdminLoginPage.tsx  ← شاشة دخول /admin (Supabase Auth)
│   │       └── AdminDashboard.tsx  ← لوحة التحكم (منتجات، أقسام، إعدادات، سوشيال، تحليلات، زر النشر)
├── server.ts                       ← سيرفر تشغيل بسيط (تطوير فقط / استضافة اختيارية على Node)
```

## 3) الفكرة المعمارية باختصار (مهم تفهمها)

```
العميل  →  يقرأ فقط من جدول site_published في Supabase  →  ما يشوفش أي تعديل غير منشور

الأدمن  →  يسجّل دخول عبر /admin (Supabase Auth)
        →  كل تعديل (منتج / قسم / سعر / صورة / رابط / نص) يتسجّل فوراً في جدول site_draft
        →  يضغط زر "🚀 رفع التعديلات"
        →  الكود بينسخ site_draft بالكامل فوق site_published دفعة واحدة
        →  Supabase Realtime يبلّغ كل المتصفحات المفتوحة إن فيه نسخة جديدة، فتحدّث نفسها تلقائياً
```

كل حقل نصي أو صورة أو رابط أو سعر يظهر للعميل هو جزء من هذا الـ JSON الموحّد
(`settings` / `categories` / `products` / `socialMedia`)، فأي إضافة مستقبلية لحقل
جديد في نموذج الأدمن تنعكس تلقائياً بدون تعديل قاعدة البيانات.

⚠️ **مهم جداً — خطوتين مش خطوة واحدة:** أي تعديل في لوحة التحكم (شعار، اسم، سعر،
صورة...) بيتحفظ بزرار "حفظ" الخاص بكل تبويب (بيتسجل في المسودة draft)، **لكنه لسه
مش ظاهر للعميل**. عشان يظهر فعلياً لازم تضغط بعد كده زرار **"🚀 رفع التعديلات"**
اللي فوق الصفحة كلها. لو حفظت بس وما ضغطتش رفع التعديلات، هتفضل الصورة/الكلام
القديم هو الظاهر للعملاء.

## 4) إعداد Supabase خطوة بخطوة

### الخطوة 1 — إنشاء المشروع
1. روح على https://supabase.com وسجّل دخول.
2. اضغط **New Project**، اختار اسم ومنطقة قريبة منك (مثلاً Frankfurt/EU)، وحط كلمة سر لقاعدة البيانات.
3. استنى دقيقة لحد ما المشروع يخلص إنشاء.

### الخطوة 2 — تشغيل ملف SQL
1. من القائمة الجانبية: **SQL Editor** → **New query**.
2. افتح ملف `schema.sql` المرفق، انسخ محتواه بالكامل، الصقه في المحرر.
3. اضغط **Run**. لازم تشوف رسالة نجاح بدون أخطاء. (آمن تشغيله أكتر من مرة).

هذا السطر ينشئ: جداول المحتوى (`site_draft`, `site_published`, `publish_history`),
جدول الأدمن (`profiles`), جدول الصور (`media_library`), جدول الإحصائيات
(`analytics_events`), كل سياسات الحماية (RLS)، وباكت تخزين الصور (`site-media`).

### الخطوة 3 — الحصول على مفاتيح المشروع
1. من القائمة الجانبية: **Project Settings** (⚙️) → **API**.
2. هتلاقي:
   - **Project URL** → هو `VITE_SUPABASE_URL`
   - **anon public key** → هو `VITE_SUPABASE_ANON_KEY`
3. **لا تستخدم أبداً** الـ `service_role key` في الموقع — ده للسيرفرات الموثوقة فقط وغير مطلوب هنا إطلاقاً.

### الخطوة 4 — وضع المفاتيح في المشروع
1. في مجلد المشروع، انسخ `.env.example` وسمّيه `.env`.
2. افتح `.env` وحط القيم اللي نسختها:
   ```
   VITE_SUPABASE_URL="https://xxxxxxxx.supabase.co"
   VITE_SUPABASE_ANON_KEY="eyJhbGciOi....."
   ```
3. احفظ الملف. (ملف `.env` متجاهل من Git تلقائياً، آمن).

### الخطوة 5 — إنشاء أول حساب أدمن
1. من القائمة الجانبية في Supabase: **Authentication** → **Users** → **Add user** → **Create new user**.
2. حط إيميل وكلمة سر (احفظهم، هتستخدمهم للدخول على `/admin`).
3. من **SQL Editor** شغّل الاستعلام ده بعد ما تستبدل الإيميل بإيميلك فعلاً:
   ```sql
   insert into public.profiles (id, email, name, role)
   select id, email, 'مدير مطعم العمدة', 'super_admin'
   from auth.users
   where email = 'ضع-إيميلك-هنا@example.com'
   on conflict (id) do nothing;
   ```
4. كده حسابك بقى مدير معترف به، وأي حساب تاني تعمله بنفس الطريقة (بدون هذا الاستعلام)
   هيقدر يسجل دخول في Supabase لكن مش هيقدر يدخل لوحة التحكم — لازم صف في `profiles`.

### الخطوة 6 — تأكيد إعدادات Storage (تفعيل الصور في Supabase خطوة بخطوة)

باكت الصور `site-media` بينعمل **تلقائياً** من `schema.sql` اللي شغّلته في الخطوة 2
(بما فيه: باكت عام + سياسات قراءة عامة + رفع/حذف للأدمن فقط). لكن للتأكيد ومعرفة
مكانه بالظبط، اعمل الآتي:

1. من القائمة الجانبية في Supabase: **Storage**.
2. المفروض تلاقي باكت اسمه **site-media** موجود، وعليه علامة **Public**.
   - لو مش لاقيه: يبقى `schema.sql` ما اتشغلش بالكامل، ارجع للخطوة 2 وشغّله تاني.
3. لو عايز تتأكد إن الرفع شغال يدوياً بنفسك (اختياري، مش لازم):
   - افتح الباكت → **Upload file** → ارفع أي صورة تجربة.
   - اضغط على الصورة → **Get URL** → افتح الرابط في تاب جديد، المفروض الصورة تظهر
     مباشرة بدون تسجيل دخول (لأن القراءة عامة).
4. الطريقة الفعلية والمقصودة لرفع الصور هي من **داخل لوحة التحكم مباشرة**، مش من
   Supabase Dashboard يدوياً:
   - `/admin` → **إدارة الأصناف** → **إضافة صنف جديد** → زر **"رفع صورة من جهازك"**.
   - أو **إدارة الأقسام** → نفس الفكرة (صورة القسم + صورة الخلفية).
   - بمجرد اختيار الصورة من جهازك، بترفع تلقائياً إلى `site-media` وترجع رابط دائم،
     وتتسجل في جدول `media_library` (تقدر تشوف كل الصور المرفوعة من SQL Editor:
     `select * from media_library order by created_at desc;`).
5. الصورة المرفوعة بتفضل في المسودة فقط لحد ما تضغط **"🚀 رفع التعديلات"** — وقتها
   بس تظهر للعميل، بالظبط زي أي تعديل تاني.

**لو صورة معينة ما ظهرتش للعميل بعد الرفع والنشر:**
- تأكد إنك ضغطت "رفع التعديلات" فعلاً بعد الرفع (مش كافي إنك ترفع بس).
- اعمل Refresh قوي للصفحة (Ctrl+Shift+R) لتفادي أي كاش قديم من المتصفح.
- تأكد إن الباكت `site-media` لسه Public من Storage → اضغط على الباكت → Settings.

## 5) تشغيل المشروع محلياً في Visual Studio Code

### المتطلبات
- **Node.js** نسخة 18 أو أحدث (يفضل 20+). تأكد بكتابة في الترمينال: `node -v`
- **VS Code** مثبت، مع إضافة **ESLint** و **Tailwind CSS IntelliSense** (اختياري لكن مفيد).

### الخطوات
1. افك ضغط ملف المشروع (ZIP) في أي مجلد على جهازك.
2. افتح المجلد في VS Code: `File → Open Folder...`
3. افتح **Terminal** جواه: `` Terminal → New Terminal `` (أو Ctrl+`).
4. ثبّت المكتبات:
   ```bash
   npm install
   ```
5. تأكد إنك عملت ملف `.env` زي الخطوة 4 فوق (لازم يكون موجود قبل التشغيل).
6. شغّل المشروع:
   ```bash
   npm run dev
   ```
7. هيفتحلك في الترمينال رابط زي `http://localhost:3000` — افتحه في المتصفح.
8. المفروض تشوف:
   - الإنترو السينمائي (~2.6 ثانية) ثم الصفحة الرئيسية.
   - لو `site_draft`/`site_published` لسه فاضيين من منتجات (لأنك لسه ما ضفتش
     حاجة من لوحة التحكم)، هتلاقي الأقسام والمنتجات فاضية — ده طبيعي، وده
     بالظبط اللي هيتظبط في الخطوة الجاية.

### اختبار لوحة التحكم
1. روح على: `http://localhost:3000/admin`
2. سجّل دخول بالإيميل وكلمة السر اللي عملتهم في الخطوة 5 فوق.
3. من تبويب **إدارة الأقسام**: ضيف قسم (مثلاً "المشويات") وارفع له صورة من جهازك.
4. من تبويب **إدارة الأصناف**: ضيف صنف جديد داخل هذا القسم.
5. من تبويب **إعدادات المطعم وواتساب**: عدّل رقم الواتساب واسم المطعم.
6. من تبويب **روابط التواصل**: عدّل روابط الثلاث بطاقات.
7. هتلاحظ شريط برتقالي أعلى الصفحة "يوجد تعديلات لم تُنشر بعد" — ده طبيعي ومقصود.
8. اضغط زر **🚀 رفع التعديلات** في أعلى الصفحة.
9. لازم تظهر رسالة نجاح خضراء، ويختفي الشريط البرتقالي.
10. ارجع للموقع (`عرض الموقع كعميل` أو `http://localhost:3000`) واعمل **Refresh**:
    كل التعديلات المفروض تكون ظاهرة فعلياً للعميل الآن.
11. جرّب تفتح الموقع من متصفح تاني أو من موبايلك على نفس الشبكة (`http://<IP الجهاز>:3000`):
    التعديلات المنشورة المفروض تظهر هناك كمان — ده دليل إن قاعدة البيانات حقيقية
    ومش مجرد تخزين محلي في المتصفح.

### بناء نسخة الإنتاج (اختياري، قبل الرفع لاستضافة حقيقية)
```bash
npm run build     # ينتج مجلد dist/ جاهز للنشر
npm start         # يشغّل نسخة الإنتاج محلياً للتجربة (بعد build)
```

## 6) النشر (Deployment) — أونلاين على دومين حقيقي

المشروع الآن **موقع ثابت (Static SPA)** بيكلم Supabase مباشرة من المتصفح، يعني
أسهل استضافة ممكنة — مفيش سيرفر Backend لازم تديره. اختر أي من:

- **Vercel** أو **Netlify**: اربط المستودع (GitHub) أو ارفع مجلد `dist/` بعد `npm run build`،
  وحط متغيرات البيئة `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` من إعدادات المشروع هناك (Environment Variables).
- **Cloudflare Pages**: نفس الفكرة (Build command: `vite build`, Output: `dist`).

بعد النشر، لا تنسَ تضيف رابط موقعك الجديد لو استخدمت أي إعدادات Redirect URLs
في Supabase Auth (Authentication → URL Configuration) عشان تسجيل الدخول يشتغل صح.

## 7) سلة الطلبات (Cart) وربطها بزر واتساب — شرح كامل

هذا نظام جديد أضفته حسب طلبك: العميل يقدر يجمع أكتر من صنف في سلة واحدة، ثم
يرسلهم كطلب واحد مُجمّع عبر واتساب.

**إزاي يشتغل من ناحية العميل:**
1. العميل يتصفح المنيو، وعلى كل كارت صنف فيه زر أخضر بأيقونة سلة 🛒 — بيضغط عليه
   فيتضاف الصنف للسلة فوراً (تظهر علامة ✔ لثانية للتأكيد).
2. أو من صفحة تفاصيل الصنف: يقدر يحدد الكمية ثم يضغط **"أضف للسلة"**.
3. عداد صغير (Badge) بيظهر على: أيقونة السلة في الهيدر، أيقونة السلة في القائمة
   السفلية بالموبايل، **وعلى زر الواتساب العائم نفسه** — يوضح عدد القطع بالسلة.
4. لما العميل يخلّص اختياره ويضغط **زر الواتساب العائم**:
   - لو السلة فيها أصناف → تنفتح **نافذة مراجعة السلة** مباشرة (مش نافذة استفسار
     عامة) تعرض كل الأصناف، الكمية، السعر، الإجمالي، ويقدر يعدّل الكمية أو يشيل صنف.
   - يختار نوع الطلب (توصيل / تيك أواي / داخل الصالة) ويكتب العنوان أو رقم الطاولة.
   - يضغط **"إرسال الطلب عبر واتساب"** → بتتفتح محادثة واتساب فيها رسالة جاهزة
     ومنسّقة بكل الأصناف والكميات والأسعار والإجمالي الكلي ونوع الطلب، جاهزة للإرسال
     مباشرة.
   - بعد الإرسال، السلة بتتفضّى تلقائياً استعداداً لطلب جديد.
   - لو السلة فاضية، الزر يفتح نافذة استفسار عامة عادية (زي الأول) للأسئلة العامة.
5. السلة نفسها محفوظة في متصفح العميل (localStorage) — يعني لو قفل الصفحة وفتحها
   تاني، سلته لسه موجودة، لحد ما يبعت الطلب أو يفضيها يدوياً.

هذا الجزء **لا يحتاج أي إعداد إضافي منك** — شغال تلقائياً بمجرد رفع المشروع، ولا
يمر بقاعدة البيانات (السلة مؤقتة في متصفح كل عميل، مش محتاجة تخزين مركزي).

## 8) إضافة / تعديل / حذف الأصناف من لوحة التحكم — تأكيد

أي صنف تضيفه الإدارة من `/admin → إدارة الأصناف → إضافة صنف جديد` بيتسجل في
المسودة فوراً، وبعدها تقدر:
- **تعديله**: اضغط على الصنف من القائمة → عدّل أي حقل (اسم، وصف، سعر، صورة، القسم،
  متاح/غير متاح، الأفضل مبيعاً...) → احفظ.
- **حذفه**: زر سلة المهملات 🗑 بجانب الصنف → تأكيد الحذف → يختفي من المسودة.
- **تفعيل/تعطيل التوفر**: زر سريع لتبديل حالة "متاح/غير متاح" بدون فتح نموذج التعديل.

كل هذا **لا يظهر للعميل فوراً** — يفضل في مرحلة المسودة لحد ما تضغط
**"🚀 رفع التعديلات"**، بالظبط زي باقي المحتوى. نفس المبدأ ينطبق تماماً على
الأقسام (إضافة/تعديل/حذف/إعادة ترتيب).

## 9) تفاصيل مهمة حسب طلبك (checklist)

- ✅ **قاعدة البيانات Supabase بالكامل** بدل Cloudflare D1 (`schema.sql` مرفق ومنفصل كمان).
- ✅ **مصادقة أدمن حقيقية** عبر Supabase Auth (إيميل + باسورد)، مفيش أي إيميل/باسورد مكتوب في الكود.
- ✅ **دخول الأدمن فقط عبر `/admin`** — مفيش أي زر أو رابط ظاهر للعميل يوديه هناك.
- ✅ **Row Level Security** مفعّلة على كل الجداول؛ العميل (زائر بدون تسجيل دخول) يقدر يقرأ
  `site_published` فقط، ولا يقدر يعدّل أي جدول إطلاقاً.
- ✅ **كل نص/صورة/رابط/سعر يظهر للعميل قابل للتعديل من الأدمن** لأنه جزء من JSON المحتوى
  الموحّد، مفيش أي نص Hardcoded في المكوّنات (اسم المطعم، الوصف، رقم الواتساب، روابط
  السوشيال ميديا، كل ده بيتقرأ من `settings`/`socialMedia` القادمة من قاعدة البيانات).
- ✅ **نظام مسودة/منشور حقيقي** + زر **"🚀 رفع التعديلات"** ينشر كل التعديلات دفعة واحدة
  (منتجات + أقسام + إعدادات + سوشيال ميديا مع بعض، مش كل حقل لوحده).
- ✅ **رفع صور حقيقي من الجهاز** إلى Supabase Storage (مش base64 داخل الكود)، مع تسجيلها
  في **مكتبة وسائط** (`media_library`) للمراجعة.
- ✅ **Realtime**: أي عميل فاتح الموقع وقت ما تنشر تعديل، الموقع عنده بيتحدّث تلقائياً
  بدون ما يحتاج يمسح الكاش.
- ✅ **اتشال نظام الكاشير بالكامل**: تبويبات "الكاشير والفواتير"، "أرشيف المبيعات وقفل
  الوردية"، و"جرد المخزن" اتشالت من لوحة التحكم، وأنواع البيانات الخاصة بيها (فواتير،
  ورديات، مخزون) اتشالت من `types.ts`. الموقع الآن **منيو وطلب عبر واتساب فقط**، زي ما طلبت بالظبط.
- ✅ **الإنترو السينمائي**: بقى فيه طبقات بصرية أكتر (توهج نابض، موجة حرارة، شرر ودخان
  صاعد، خط ضوء ذهبي يعبر الشاشة مرة واحدة، حلقتين دوّارتين حول الشعار) لكن بردو بسيط
  ومريح للعين ومحدود المدة (~2.6 ثانية) زي ما طلبت ("مبهر بس مش أوفر"). الخلفية الحية
  (`AmbientBackground`) شغالة قبل وبعد الإنترو بنفس الطبقة، فالانتقال إحساسه متصل
  مش قطع مفاجئ.
- ✅ **بطاقات السوشيال ميديا**: مكوّن واحد عام (`SocialMediaCards`) داخل الفوتر العام
  (`Footer`) الظاهر تلقائياً في كل صفحة عميل (الرئيسية، المتجر/الأقسام، تفاصيل القسم،
  الأفضل مبيعاً، المفضلة، صفحة المنتج). 3 بطاقات جنب بعض في صف واحد دايماً على
  الموبايل (`grid-cols-3` ثابتة)، ومتحكم فيها بالكامل (المنصة، العنوان، الرابط، الترتيب،
  التفعيل) من تبويب "روابط التواصل" في لوحة التحكم.
- ✅ **بدون صوت نهائياً**: ملف تركيب الصوت غير المستخدم اتشال من المشروع.
- ✅ **سلة طلبات حقيقية مربوطة بواتساب**: العميل يجمع أكتر من صنف، يعدّل الكميات،
  ويبعتهم كطلب واحد منظم عبر واتساب بضغطة واحدة (تفاصيل كاملة في القسم 7 فوق).
- ✅ **كل صنف تضيفه الإدارة قابل للتعديل والحذف بالكامل** في أي وقت من نفس الشاشة
  (تفاصيل في القسم 8 فوق).

## 10) نقاط مهمة للانتباه (Honesty Note)

- المشروع ده **بُني على قاعدة الكود الحقيقية اللي رفعتها**، مش مشروع جديد من الصفر —
  كل تعديل اتعمل داخل نفس الملفات والمكوّنات الأصلية بتاعتك عشان تفاصيل التصميم
  (الألوان، الخطوط، تجربة كل صفحة) تفضل زي ما هي بالظبط.
- بما إني اشتغلت بدون اتصال إنترنت هنا، **معرفتش أشغّل `npm install` أو أعمل build فعلي
  للتأكد 100%**، فبعد أول تشغيل عندك لو ظهر أي خطأ صغير في الترمينال (نادر لكن وارد)،
  ابعتلي رسالة الخطأ بالظبط وهساعدك تحله فوراً.

  الرئيسية)، النمط ثابت: ضيف الحقل في `types.ts` → ضيف عنصر إدخال له في
  `AdminDashboard.tsx` → هيتخزن ويتنشر تلقائياً بنفس آلية باقي الحقول، بدون أي تعديل
  في قاعدة البيانات.
